# Касса школьного класса — отчёт для родителей

Статическая страница, которую видят родители. Публикуется через GitHub Pages.
Данные на странице зашифрованы: без кода виден только запрос кода. Имена детей
на странице полные — см. «Имена на странице», там же о том, чем за это платим.
Репозиторий не привязан к номеру класса: в 3В, 4В и дальше используется он же,
меняется только содержимое журнала.

## Что здесь лежит

- `tools/build.sh` — **точка входа**, единственный способ собрать отчёт: и
  публичную версию, и именную. Смотри «Как собрать страницу».
- `tools/build_report.py` — **генератор**, единственный исходник страницы.
  Все правки вносятся сюда: и вёрстка, и логика, и тексты.
- `tools/journal.py` — границы данных в журнале: где начинается и кончается
  каждый список. Общий для генератора и проверки, см. «Границы списка».
- `.env.local` — код доступа строкой `PASSWORD=...`. В репозиторий не попадает,
  создаётся руками на каждой машине.
- `index.html` — **артефакт сборки, а не исходник**. Собирается генератором,
  руками не правится: следующая сборка затрёт правки без предупреждения.
  Имя менять нельзя, Pages ищет именно `index.html`.
- `archive/` — отчёты прошлых учебных лет, по файлу на год (`2026-2027.html` и так далее).
- `robots.txt` и `<meta name="robots" content="noindex">` внутри страницы — запрет индексации.
- `.nojekyll` — отключает обработку Jekyll, чтобы GitHub отдавал файлы как есть.
- `manifest.json` — имя, цвета и иконки для ярлыка на экране «Домой»
  (`assets/icon-512.png` и `apple-touch-icon.png`). Подключается из `<head>`,
  который живёт в генераторе.

### Почему не включён standalone-режим

Вопрос закрыт: `apple-mobile-web-app-capable` не добавляем, ярлык открывает
страницу в обычном Safari с адресной строкой. Причина в том, что standalone
на iOS — это отдельное приложение со своим хранилищем:

- сохранённый в Safari код доступа туда не подставляется, и родитель,
  один раз доверивший код браузеру, будет вводить его заново;
- пропадает кнопка «Поделиться» — переслать ссылку другому родителю нельзя.

Страницу открывают раз в месяц, адресная строка не мешает. Автозаполнение
кода и возможность скопировать ссылку важнее полноэкранного режима.

## Откуда берутся данные

Журнал кассы за текущий учебный год:
`Google Drive / For_sorting / Школа / Класс_Артура / <учебный год> / Свод / Касса_*.xlsx`.

Чтобы поменять цифры — меняют журнал и пересобирают страницу. Не наоборот.

График платежей берётся с листа **«График»**: `B` сбор (точное название, как на
листе «Сборы»), `C` дата, `D` сумма, `E` комментарий; читаются строки 6–45.
Каждый шаг попадает и в карточку сбора, и в календарь отдельным сроком, поэтому
разбивку платежей меняют здесь, а не в вёрстке. Сбор без строк на этом листе
собирается по-старому — одной датой первого взноса.

Внешние плательщики отмечаются на листе **«Ученики»**, колонка `L` (комментарий):
если он начинается со слов «Не ученик», строка считается не ребёнком класса.
Так в кассу попадают чужие деньги — например, соседний класс, делящий кабинет,
скинулся на общий декор. Такая строка не идёт ни в чипы, ни в основную таблицу
на вкладке «По детям» и не участвует в делении расходов (доля считается только
на детей). Её остаток показан отдельным блоком «Поступления не от учеников
класса» под таблицей: деньги лежат в общей кассе, и без этого блока сумма
видимых остатков не сходится с остатком кассы.

Тем же признаком помечен **учитель класса**: строка «Не ученик класса: учитель»
с датой рождения в колонке `K`. Ключевое слово «учитель» в пометке отличает её от
плательщика: денег за учителем нет, и в блок поступлений он не идёт — там место
только строкам с ненулевой суммой. Строка нужна ради одного — дня рождения в
календаре. **Имя из колонки `C` на страницу не выводится вовсе:** там может стоять
настоящее ФИО, а в календаре показывается подпись `TEACHER_LABEL` из генератора.
Строки нет — в календаре просто нет дня рождения учителя, сборка не падает.

Технические строки дописывают **в конец списка**, не вставляя выше: колонка
участника на листах «Участие», «Долги_год», «Долги_срок» вычисляется из номера
строки (`col = MC + (r - S_FIRST)`), и вставка сдвинула бы колонки у всех, кто ниже.
Вставка теперь не проходит молча — см. «Границы списка», — но чинить её всё равно
руками, поэтому проще дописывать в конец. Дату рождения пишут в том же виде, что
у детей — текстом `ДД.ММ.ГГГГ`; год не показывается, для технической строки он
может быть любым.

### Границы списка

Класс растёт посреди года, и запаса строк под список рано или поздно не хватает:
его расширяют, `ИТОГО` уезжает вниз, колонки участников в матрицах прибавляются.
Границы, записанные в коде числом, в этот день начинают **молча терять данные** —
цикл по слишком короткому диапазону не падает, он просто не доходит до последних
детей. Так уже было дважды.

Поэтому в коде их больше нет. `tools/journal.py` читает границы каждого листа
оттуда же, откуда их читает человек:

- сверху — строка шапки, по подписи первой колонки в `B` (`№`, `Код`, `Дата`, `Срок`, `Сбор`);
- снизу — строка `ИТОГО…`, которой кончается каждый лист.

Отсюда следуют два правила для журнала. **Строку `ИТОГО` нельзя удалять и
переименовывать** — это конец данных, без неё сборка останавливается. И **всё,
что не данные, пишется ниже `ИТОГО`**: на листе «Ученики» под итогом лежат две
заметки, и именно поэтому низ списка нельзя искать «последней непустой строкой» —
непустые строки на листе есть и ниже итога.

Пустые строки запаса между последней записью и `ИТОГО` безвредны: строка без
ключевого поля пропускается. Расширять запас можно свободно — расширили список
с 22 строк до 30, ничего в коде не трогали.

Отдельно проверяется связь «строка ученика → колонка матрицы». Она нигде не
записана, вычисляется арифметикой и разъезжается беззвучно: отчёт соберётся,
просто у части детей будут чужие долги. Сверять есть с чем — в шапке «Участия»,
«Долгов_год» и «Долгов_срок» стоят те же имена, что в колонке `C` списка. Они и
сравниваются, строка за строкой, включая пустые строки запаса (пустой строке
обязана отвечать пустая колонка). Расхождение останавливает сборку с указанием
строки, колонки и обоих имён.

Вторая линия — `tools/verify.py`: он пересчитывает список по журналу заново и
сверяет с числом детей на собранной странице. Генератор потерю не заметит — у
него в отчёте ровно то, что он прочитал, — поэтому считает независимо тот, кто
смотрит на готовый файл.

`tools/verify.py` следит, чтобы колонка `C` таких строк не попала на страницу:
для каждой строки «Не ученик…» без денег он ищет её содержимое и в расшифрованном
payload, и в разметке. Это строже проверки по шаблону: шаблон поймал бы только имя
не той формы, а поиск подстроки ловит любое попадание, включая тот день, когда
кто-нибудь начнёт брать подпись из колонки `C`. Строки с деньгами
(«Соседи») из проверки исключены: их имя на странице по замыслу. Чтобы проверка
работала, `build.sh` передаёт `verify.py` путь к журналу через `SRC`; запущенный
руками без `SRC` verify честно печатает, что эта проверка не выполнялась.

Сама эта проверка — вторая линия обороны, а не первая: у технической строки от
колонки `C` не берётся **ни одного поля, включая производные**, потому что утечь
может часть имени, а не имя целиком. Так и было: существовало поле `first` (имя
для сортировки участников), выводившееся как второе слово колонки `C` — для
«Учитель класса» оно давало «класса», а для настоящего ФИО отдало бы настоящее
имя, и поиск подстроки полного имени такого не поймал бы. Поля больше нет вовсе:
после возврата полных имён сортировать стало по самому имени, и производить из
колонки `C` нечего.

Обещанное, но не оплаченное лежит на листе **«Обязательства»**: `B` срок,
`C` сбор, `D` на что, `E` сумма, `F` кому / где, `G` комментарий; читаются
строки 6–25, пустая сумма — пустая строка. Это то, о чём договорились, но
деньги ещё на карте, поэтому в «Расходы» такие строки не попадают: иначе
журнал разойдётся с фактическим остатком. На странице они идут отдельным
блоком над списком трат и в плитку «Свободный остаток», но **не** в календарь
(срок там ориентировочный) и **не** в долю расходов на ребёнка — доля
считается только по тому, что уже потрачено. Когда оплата проходит, строку
переносят в «Расходы», а отсюда удаляют. Листа может не быть вовсе — тогда
блок и плитка просто не выводятся.

Адресная часть траты лежит на листе **«Личные списания»**: `B` дата, `C` сбор,
`D` ребёнок (имя как на «Учениках», слово в слово), `E` за что, `F` сумма,
`G` подтверждение, `H` комментарий; шапка в строке 5, данные 6–65, заполненной
считается строка, где есть и ребёнок, и сумма. Правило родкома от 03.09.2026:
расходную вещь, доставшуюся конкретным детям, оплачивает тот, кому она
досталась, а не весь класс; запасные экземпляры делятся на всех.

Этот лист ничего не добавляет к «потрачено» — сама трата целиком уже лежит в
«Расходах». Он только делит её иначе: общая часть расходов сбора идёт поровну
всем участникам (колонка `O` «Сборов»), а личное списание — сверх неё тому, кому
вещь досталась. Доля ребёнка в журнале (колонка `I` «Учеников») это уже
учитывает, страница повторяет расчёт и показывает, из чего доля сложилась:
в раскрытой строке ребёнка появляется блок «Из чего сложилась доля расходов» —
общая часть, список личных строк с датой, суммой и подтверждением, итог. У кого
личных списаний нет, блока нет вовсе; пустой лист (или его отсутствие) страницу
не меняет ничем.

**Долгом это не становится.** Личное списание уменьшает «не потрачено», а
«должен за год» и «к сроку» не трогает: по графику взносов такой ребёнок должен
ровно столько же, сколько все. Долги по-прежнему берутся только с матриц
«Долги_год» и «Долги_срок».

Сборка останавливается, если имя на «Личных списаниях» не нашлось в списке
класса, если списание привязано к сбору, в котором ребёнок не участвует, или
если доля из колонки `I` «Учеников» не сошлась с суммой долей по сборам. Любая
из этих трёх — это разные числа об одном и том же в соседних блоках карточки,
и тихо пройти они не должны. `tools/verify.py` дополнительно сверяет, что общая
часть у всех детей одна и что сумма всех долей равна «потрачено».

Расход может быть **отрицательным**: это возмещение — деньги вернулись в кассу.
Так проведены 600 ₽ от соседнего класса за общее оформление: не взносом (взнос
достался бы одному плательщику и потребовал бы отдельного сбора), а строкой со
знаком минус в «Расходах». Тогда возврат уменьшает и общие расходы, и долю
каждого ребёнка поровну — чего и просил родком. Считать такую строку обычной
арифметикой можно и нужно: она входит в «потрачено», в итог своей группы и в
долю на ребёнка со своим знаком, поэтому итог направления бывает меньше
отдельной траты в нём, а итог дня — уйти в минус. На странице возмещение
отличается от траты подписью «возмещение» и цветом остатка, а не долга: красный
здесь читался бы как ошибка.

Комментарий к расходу — лист **«Расходы»**, колонка `J` — выводится родителям:
строка на вкладке «Расходы» раскрывается нажатием и показывает расшифровку
(что вошло в чек). Строка без комментария не раскрывается. Это лучший ответ на
вопрос «куда ушли деньги», чем категория, поэтому расшифровки стоит заполнять.
Комментарий к взносу — лист **«Взносы»**, колонка `I` — тоже выводится: он стоит
мелким шрифтом под платежом в раскрытой строке ребёнка и говорит, откуда взялась
запись. У большинства платежей это «из паровозика в родительском чате», но бывает
перевод личным сообщением без чека — и родителю важно видеть, на чём держится
строка в его отчёте, а не только сумму. Соседняя колонка `H`
(«Подтверждение (файл)») наружу **не** идёт: там имя файла с фамилией ребёнка.

Комментарий к сбору (лист **«Сборы»**, колонка `Q`) на страницу не идёт: это
заметка для казначея.

Служебные пометки в комментариях («[?]», «уточнить», «уточняется», «TODO», «??»)
в журнале допустимы как временные, но на страницу попадать не должны — родитель
читает их как часть отчёта. `tools/verify.py` ищет их в собранной странице и
падает с указанием записи и поля.

Итоги для шапки берутся с листа **«Свод»** по подписи в колонке `B`
(«Поступило всего», «Остаток кассы», «Свободный остаток» и так далее), а не по
номеру строки: строки на листе сдвигаются при появлении новых итогов. Если
подпись переименовать, сборка остановится с явной ошибкой, а не подставит ноль.

## Что на странице считается долгом

Главное число долга — **годовое**: сколько ребёнку (или классу) осталось внести
до полной суммы сбора. Срок — расшифровка под ним: какая часть этой суммы нужна
к ближайшей дате графика.

До 27.08.2026 было наоборот, и это вводило в заблуждение. Пример из данных того
дня: Воробушкина внесла 3 000, к сроку 30.09 должна 0 — страница показывала ноль,
и родитель читал его как «ничего не должен». А за год ей оставалось внести 2 000,
и этого числа на странице не было ни в одном месте.

Где это видно:

- **плитка в шапке** — «Осталось внести за год» (`Ждём за год всего` на «Своде»),
  под суммой «из них … до 30.09»;
- **строка ребёнка** — колонка «Должен за год», под суммой мелким либо
  «из них … до 30.09», либо «ближайший срок закрыт»; красным выделены только те,
  у кого ближайший платёж ещё не закрыт;
- **раскрытая строка** — расшифровка деньгами и оставшиеся платежи по графику;
- **карточка сбора** — «должны за год», следом «из них к сроку».

Фильтры на вкладке «По детям» делят по главному вопросу: «Все», «Есть долг за
год», «Рассчитались». Прежние «Надо к сроку» и «Только за год» делили по сроку —
он теперь вторичен и виден прямо в строке, переключать ради него фильтр не нужно.

**«Не потрачено» — не «долга нет».** Так называется бывший «Остаток»: деньги
ребёнка, ещё не ушедшие в расходы (внесено минус своя доля). Долг и не
потраченные деньги — разные вещи и прекрасно уживаются: у той же Воробушкиной
2 230,29 ₽ не потрачено и 2 000 ₽ долга за год.

**Просрочки на странице нет.** Шаг графика, чья дата прошла, не показывается
отдельной красной датой: он входит в планку ближайшего срока — ровно так, как
его считает журнал. В разбивке «осталось внести по графику» такие шаги
схлопнуты в одну строку с датой ближайшего срока. Поэтому первый шаг разбивки
всегда равен «из них к сроку», а сумма всех шагов — «осталось за год»; если
после подсчёта они не сходятся с журналом, разбивка не показывается вовсе.

## Имена на странице

Имена детей выводятся **полностью, в формате журнала: «Фамилия Имя»** —
«Елисеев Артур». Раньше страница показывала «Артур Е.», фамилия в файл не
попадала вовсе.

Решение родкома от 27.08.2026: с 26 детьми подпись «Артур Е.» неудобно искать
глазами в списке. Риск обсуждали и приняли осознанно. Он такой: **код доступа
знают все семьи класса, и при утечке кода наружу уходят фамилия, имя, день
рождения и долг каждого ребёнка.** Код при этом оставлен прежним — то есть
защита не усилилась, а объём того, что она закрывает, вырос.

Отсюда несколько следствий, которые стоит держать в голове:

- **Шифрование теперь единственная линия защиты.** Маскировка была второй, и её
  нет. Поэтому сборка без `PASSWORD` остановлена жёстче прежнего — см.
  «Предохранитель».
- **Формат меняется в одном месте** — функция `pub()` в `tools/build_report.py`.
  Она оставлена именно как эта точка, хотя сейчас и возвращает имя как есть.
- **Порядок «Фамилия Имя» не косметика.** Список отсортирован по фамилии, как
  бумажный список класса, и поиск по строке находит и по фамилии, и по имени.
- **Сортировка по имени и по фамилии — это одно и то же**, поэтому на вкладке
  «По детям» ключ сортировки по имени один (заголовок «Ученик»).

Что полными именами **не** стало:

- **Казначей** подписан коротко — «Анна Е.», константа `TREASURER_LABEL`.
  Решение родкома касалось списка детей; про казначея речи не было, а её фамилия
  — такие же персональные данные третьего лица. Одна строка, если решат иначе.
- **Учитель класса.** Колонка `C` его строки на страницу не идёт по-прежнему:
  там может стоять настоящее ФИО, а в календаре показывается подпись
  `TEACHER_LABEL` из генератора. Это ограничение к маскировке отношения не имело
  и осталось в силе — `tools/verify.py` его проверяет.

Что проверяет `verify.py` вместо снятой проверки маски: что имена на странице
**совпадают с журналом слово в слово** — и в списке детей, и в списках участников
внутри сборов. Шаблон «Артур Е.» ловил сборку без маскировки; на его месте
осмысленна обратная проверка — что имя не потерялось и не съехало по дороге.
Она видит и перепутанные строки, и обрезанное имя, чего шаблон формы не видел.

## Как собрать страницу

Один раз — зависимости и код доступа:

```bash
python3 -m venv .venv
.venv/bin/pip install openpyxl cryptography
printf 'PASSWORD=код\n' > .env.local
```

Дальше вся сборка — один скрипт `tools/build.sh`:

```bash
./tools/build.sh                     # публичная версия на сегодня → index.html
./tools/build.sh 2026-08-17          # то же, но задним числом
./tools/build.sh 2026-08-17 --named  # именная версия → папка Свод на Диске
```

Скрипт печатает `report ok · N сборов · M детей` — числа стоит сверить с
журналом — и сразу прогоняет `tools/verify.py`. Если verify вернул не ноль,
скрипт падает: такой файл не публикуют. Именную версию verify не проверяет:
шифрования там нет по замыслу (см. «Именная версия для казначея»).

Единственный аргумент — дата отчёта, `ГГГГ-ММ-ДД`, по умолчанию сегодня. Из неё
выводятся и `AS_OF`, и `STAMP`, поэтому дата в заголовке и метка версии в подвале
разойтись не могут. Несуществующая дата (`2026-02-31`) отбивается до чтения журнала.

### Страницу надо пересобирать после каждой даты графика

Планка «к сроку» пересчитывается только в момент сборки: живая страница
сама себя не обновляет. Значит после каждой даты графика страницу надо пересобрать,
даже если новых платежей не было, — иначе родители видят вчерашнюю планку.

Замирают две разные вещи, и обе на дате сборки. `TODAY` внутри отчёта — константа
из `AS_OF`; от неё зависит всё, что страница считает сама: какой шаг графика
подсвечен, какие серые, «через N дн.» в календаре, рамка текущего месяца, окно
блока «Ближайший месяц». А сами суммы к сроку страница не считает вовсе — она
берёт их готовыми с листов журнала («Ждём к ближайшему сроку» на «Своде»,
«Долги_срок» по детям). Поэтому перед пересборкой журнал должен быть пересчитан:
формулы там опираются на `TODAY()`, и в файл попадает то значение, которое
сохранилось при последнем пересчёте.

Оттуда же — из колонки «Ближайший срок» листа «Сборы» — берётся **дата**, которая
стоит рядом с планкой: в подписи плитки «Осталось внести за год», в строке
«из них к сроку» карточки сбора и под суммой у каждого ребёнка. Сумма и её дата
приходят из одного пересчёта и разойтись не могут, но непересчитанный журнал
состарит их обе разом. В коде дата не записана нигде: планка едет с каждым шагом
графика, и через месяц там будет 31.10.

По нынешнему графику ближайшие такие даты: **30.09**, **31.10**, **30.11**.
Актуальный список всегда виден на листе «График» и в шагах графика на самой
странице.

Пока страницу не пересобрали, на ней уживаются два разных счёта времени: деньги
замерли на дате сборки, а календарь живой и считает дни от настоящего сегодня.
Чтобы они не давали двух ответов на один вопрос, подпись плитки «Осталось внести
за год» сама признаётся в отставании: если срок из подписи уже прошёл, к ней
дописывается «срок прошёл, сумма посчитана на …: платежи после этой даты сюда не
попали». Сумму при этом никто не пересчитывает — страница не знает платежей,
прошедших после сборки, и, подняв планку сама, назвала бы должником того, кто
заплатил.

С другой стороны живого календаря — прошедшие события. Даты графика, даты
мероприятий и планируемые события **разовые**: у каждого свой год, и, пройдя,
они просто уходят из календаря. Переносить их на год вперёд нельзя — «Внести
2 000 ₽ до 25.08» это первый взнос конкретного сбора, в августе следующего года
его уже не будет, а красная строка звала бы платить второй раз. Ежегодны только
дни рождения: у них года нет вовсе, и они переносятся на следующий.

Код доступа в скрипте не записан: он читается из `.env.local` в корне
репозитория, строкой `PASSWORD=...`. Файл закрыт `.gitignore`. Если файла нет
или пароль пуст — сборка останавливается и говорит, что создать, а не собирает
страницу в открытом виде.

Почему скрипт, а не команда руками: правило в `.claude/settings.local.json`
записано один раз как `Bash(./tools/build.sh *)` и не зависит от даты. Раньше
там лежала команда с полным набором переменных, но без `AS_OF` и `STAMP` —
любая пересборка задним числом требовала подтверждения, а правило с зашитой
датой протухло бы на следующий день.

### Переменные окружения

`tools/build.sh` выставляет их сам. Таблица нужна, когда генератор запускают
напрямую — например при отладке.

| Переменная | Обязательна | Что делает |
|---|---|---|
| `SRC` | да | Путь к журналу `.xlsx` |
| `OUT` | да | Куда писать результат (для публикации — `index.html`) |
| `PASSWORD` | да | Код доступа. Данные шифруются AES-256-GCM, ключ через PBKDF2-SHA256 |
| `AS_OF` | нет | Дата отчёта в формате `ГГГГ-ММ-ДД`. По умолчанию — сегодня |
| `STAMP` | нет | Метка версии в подвале. По умолчанию — текущие дата и время `ДД.ММ.ГГГГ ЧЧ:ММ` |
| `ALLOW_UNSAFE` | нет | `1` — снимает проверку `PASSWORD`. См. ниже, в норме не нужна |

Переменной `MASK` больше нет: она включала маскировку имён, а с 27.08.2026 имена
на странице полные. См. «Имена на странице».

### Предохранитель

`PASSWORD` — не просто опция, а единственное, что закрывает страницу от
постороннего. Генератор проверяет его **до чтения журнала** и останавливает
сборку: с пустым паролем payload лёг бы в HTML как есть, и фамилию, имя, день
рождения и долг каждого ребёнка прочитал бы любой, кто открыл ссылку или скачал
файл.

Раньше рядом стояла вторая проверка, на `MASK`. Её нет, и это осознанно: флаг
включал маскировку имён, маскировки больше нет, а флаг, который ничего не делает,
но обязателен, читается следующим человеком как вторая линия защиты — которой
нет. Проверка `PASSWORD` от него никогда не зависела и работает по-прежнему.

Проверку `tools/build.sh` запускает сам, но её можно прогнать и отдельно —
например над файлом, собранным раньше:

```bash
PASSWORD='код' .venv/bin/python tools/verify.py index.html
```

`tools/verify.py` расшифровывает payload собранной страницы и смотрит на то,
что реально лежит в файле, а не на то, что генератор напечатал в конце сборки:
число детей, сборов и расходов, итоги, сходится ли арифметика, совпадает ли
список класса с журналом и совпадают ли сами имена (см. «Границы списка» и
«Имена на странице»), коротка ли подпись казначея, не осталось ли открытых данных
payload и не уехали ли на страницу служебные пометки. Выход `1` — хотя бы одна проверка упала, такой
файл не публикуют.

#### Именная версия для казначея

Ровно один сценарий, в котором `ALLOW_UNSAFE=1` законен: **незашифрованная
версия для казначея.** Собирается тем же скриптом:

```bash
./tools/build.sh 2026-08-17 --named
```

Файл пишется в `Свод/Отчёт_именной_2В.html` — **рядом с журналом на Google
Диске, не в репозиторий**. Пересобирать его стоит вместе с публичной версией:
именная от старой даты — это отчёт без последних трат и обязательств.

Что скрипт проверяет до сборки, чтобы незашифрованный файл не уехал в публикацию:

- каталог назначения лежит на Google Диске и **не** внутри рабочей копии
  (обе проверки — на случай, если `SRC` переопределили);
- `Отчёт_именной_2В.html` закрыт `.gitignore` — страховка на случай, если такой
  файл всё же окажется рядом и попадёт под `git add -A`.

Остальное на людях: файл не уходит на Pages и не пересылается в родительский чат.

Во всех остальных случаях `ALLOW_UNSAFE` не ставят: если сборка упала —
это сработавший предохранитель, а не помеха, и чинить надо `PASSWORD`.

**Стоит ли эта версия того, чтобы её держать.** Раньше она давала Ане то, чего
публичная не давала: фамилии. Теперь фамилии есть в обеих, и единственное её
отличие — отсутствие шифрования, то есть она открывается без кода. Код Аня знает
заведомо: она его и раздаёт. Получается файл со всеми данными класса открытым
текстом, лежащий в синхронизируемой папке, ради экономии одного ввода кода.
Решение за родкомом; здесь — оценка: пользы почти не осталось, а риск прибавился.
Пока не решили иначе, `--named` работает как работал.

### Код доступа

Данные шифруются AES-256-GCM, ключ выводится из кода через PBKDF2-SHA256,
**600 000 итераций**. Расшифровка идёт в браузере родителя, на сервер код не уходит.

Код **нечувствителен к регистру**, краевые пробелы срезаются: `Money2026`,
`money2026` и `MONEY2026` открывают отчёт одинаково. Это сделано ради телефона,
где включена автозаглавная буква и легко прилетает пробел из буфера.

Нормализация и число итераций продублированы в двух местах и обязаны совпадать:

- `norm_pass()` и `PBKDF2_ITERS` в `tools/build_report.py`;
- `decryptPayload()` на странице — итерации подставляются туда из `PBKDF2_ITERS`
  через `__ITERS__`, поэтому разойтись они не могут; нормализацию при правке
  нужно менять руками в обоих местах.

Если правило нормализации изменить, старые собранные страницы не откроются
прежним кодом — их нужно пересобрать.

Смена кода = пересборка страницы: код зашит в шифротекст, а не хранится рядом.
После пуша старый код перестаёт работать сразу, новый надо разослать родителям.

Сам код прописан в двух местах, и при смене правят оба:

1. заметка `Свод/_Доступ_к_сайту.md` на Google Диске — то, что читают люди;
2. `.env.local` в корне репозитория, строка `PASSWORD=...` — то, что читает
   `tools/build.sh`. Файл закрыт `.gitignore`.

Раньше код лежал ещё и в `.claude/settings.local.json`: команды сборки были
записаны там целиком, вместе с паролем, чтобы не разрешать запуск произвольного
python. Теперь разрешение выдано скрипту (`Bash(./tools/build.sh *)`), а пароль
из правил ушёл — менять его в двух местах вместо трёх и нечему разъезжаться.

### Дата отчёта

Задаётся первым аргументом скрипта в формате `ГГГГ-ММ-ДД`, по умолчанию —
сегодняшняя дата. Она идёт в заголовок страницы, в подвал и служит точкой
отсчёта для «через N дней» в календаре событий. Пересобрать отчёт задним числом:

```bash
./tools/build.sh 2026-09-01
```

Метка версии в подвале (`STAMP`) выводится из той же даты, отдельно её не
задают: иначе заголовок и подвал могли бы разъехаться.

### Доступ к Google Drive на macOS

Файлы в `~/Library/CloudStorage` защищены системой. Если сборка падает с
`PermissionError: Operation not permitted`, нужно выдать терминалу доступ:
Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску →
добавить приложение терминала и перезапустить его.

## Как обновить сайт

```bash
git add -A
git commit -m "отчёт на <дата>"
git push
```

Через минуту страница по ссылке обновится сама. Ссылка не меняется никогда.

## Смена учебного года

1. Скопировать текущий `index.html` в `archive/<год>.html`.
2. Поправить путь к журналу (`SRC`) в `tools/build.sh` и пересобрать.
3. Закоммитить и запушить. Ссылка в родительском чате остаётся прежней.

## Настройка Pages (один раз)

Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save.
