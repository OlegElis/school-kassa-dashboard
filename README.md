# Касса школьного класса — отчёт для родителей

Статическая страница, которую видят родители. Публикуется через GitHub Pages.
Данные на странице зашифрованы: без кода виден только запрос кода.
Репозиторий не привязан к номеру класса: в 3В, 4В и дальше используется он же,
меняется только содержимое журнала.

## Что здесь лежит

- `tools/build.sh` — **точка входа**, единственный способ собрать отчёт: и
  публичную версию, и именную. Смотри «Как собрать страницу».
- `tools/build_report.py` — **генератор**, единственный исходник страницы.
  Все правки вносятся сюда: и вёрстка, и логика, и тексты.
- `.env.local` — код доступа строкой `PASSWORD=...`. В репозиторий не попадает,
  создаётся руками на каждой машине.
- `index.html` — **артефакт сборки, а не исходник**. Собирается генератором,
  руками не правится: следующая сборка затрёт правки без предупреждения.
  Имя менять нельзя, Pages ищет именно `index.html`.
- `archive/` — отчёты прошлых учебных лет, по файлу на год (`2026-2027.html` и так далее).
- `robots.txt` и `<meta name="robots" content="noindex">` внутри страницы — запрет индексации.
- `.nojekyll` — отключает обработку Jekyll, чтобы GitHub отдавал файлы как есть.
- `manifest.json` — имя, цвета и иконки для ярлыка на экране «Домой»
  (`assets/icon-512.png` и `apple-touch-icon.png`). Подключается из `<head>`,
  который живёт в генераторе.

### Почему не включён standalone-режим

Вопрос закрыт: `apple-mobile-web-app-capable` не добавляем, ярлык открывает
страницу в обычном Safari с адресной строкой. Причина в том, что standalone
на iOS — это отдельное приложение со своим хранилищем:

- сохранённый в Safari код доступа туда не подставляется, и родитель,
  один раз доверивший код браузеру, будет вводить его заново;
- пропадает кнопка «Поделиться» — переслать ссылку другому родителю нельзя.

Страницу открывают раз в месяц, адресная строка не мешает. Автозаполнение
кода и возможность скопировать ссылку важнее полноэкранного режима.

## Откуда берутся данные

Журнал кассы за текущий учебный год:
`Google Drive / For_sorting / Школа / Класс_Артура / <учебный год> / Свод / Касса_*.xlsx`.

Чтобы поменять цифры — меняют журнал и пересобирают страницу. Не наоборот.

График платежей берётся с листа **«График»**: `B` сбор (точное название, как на
листе «Сборы»), `C` дата, `D` сумма, `E` комментарий; читаются строки 6–45.
Каждый шаг попадает и в карточку сбора, и в календарь отдельным сроком, поэтому
разбивку платежей меняют здесь, а не в вёрстке. Сбор без строк на этом листе
собирается по-старому — одной датой первого взноса.

Внешние плательщики отмечаются на листе **«Ученики»**, колонка `L` (комментарий):
если он начинается со слов «Не ученик», строка считается не ребёнком класса.
Так в кассу попадают чужие деньги — например, соседний класс, делящий кабинет,
скинулся на общий декор. Такая строка не идёт ни в чипы, ни в основную таблицу
на вкладке «По детям» и не участвует в делении расходов (доля считается только
на детей). Её остаток показан отдельным блоком «Поступления не от учеников
класса» под таблицей: деньги лежат в общей кассе, и без этого блока сумма
видимых остатков не сходится с остатком кассы.

Тем же признаком помечен **учитель класса**: строка «Не ученик класса: учитель»
с датой рождения в колонке `K`. Ключевое слово «учитель» в пометке отличает её от
плательщика: денег за учителем нет, и в блок поступлений он не идёт — там место
только строкам с ненулевой суммой. Строка нужна ради одного — дня рождения в
календаре. **Имя из колонки `C` на страницу не выводится вовсе:** там может стоять
настоящее ФИО, а в календаре показывается подпись `TEACHER_LABEL` из генератора.
Строки нет — в календаре просто нет дня рождения учителя, сборка не падает.

Технические строки дописывают **в конец списка**, не вставляя выше: колонка
участника на листах «Участие», «Долги_год», «Долги_срок» вычисляется из номера
строки (`col = MC + (r - S_FIRST)`), и вставка сдвинула бы колонки у всех, кто ниже.
Дату рождения пишут в том же виде, что у детей — текстом `ДД.ММ.ГГГГ`; год не
показывается, для технической строки он может быть любым.

`tools/verify.py` следит, чтобы колонка `C` таких строк не попала на страницу:
для каждой строки «Не ученик…» без денег он ищет её содержимое и в расшифрованном
payload, и в разметке. Это строже проверки шаблона «Имя Ф.» — она поймала бы только
неверно замаскированное имя, а поиск подстроки ловит любое попадание, включая тот
день, когда кто-нибудь начнёт брать подпись из колонки `C`. Строки с деньгами
(«Соседи») из проверки исключены: их имя на странице по замыслу. Чтобы проверка
работала, `build.sh` передаёт `verify.py` путь к журналу через `SRC`; запущенный
руками без `SRC` verify честно печатает, что эта проверка не выполнялась.

Сама эта проверка — вторая линия обороны, а не первая: у технической строки от
колонки `C` не берётся **ни одного поля, включая производные**, потому что утечь
может часть имени, а не имя целиком. Так и было: поле `first` (имя для списков
участников) выводилось как второе слово колонки `C` — для «Учитель класса» оно
давало «класса», а для настоящего ФИО отдало бы настоящее имя, и поиск подстроки
полного имени такого не поймал бы.

Обещанное, но не оплаченное лежит на листе **«Обязательства»**: `B` срок,
`C` сбор, `D` на что, `E` сумма, `F` кому / где, `G` комментарий; читаются
строки 6–25, пустая сумма — пустая строка. Это то, о чём договорились, но
деньги ещё на карте, поэтому в «Расходы» такие строки не попадают: иначе
журнал разойдётся с фактическим остатком. На странице они идут отдельным
блоком над списком трат и в плитку «Свободный остаток», но **не** в календарь
(срок там ориентировочный) и **не** в долю расходов на ребёнка — доля
считается только по тому, что уже потрачено. Когда оплата проходит, строку
переносят в «Расходы», а отсюда удаляют. Листа может не быть вовсе — тогда
блок и плитка просто не выводятся.

Комментарий к расходу — лист **«Расходы»**, колонка `J` — выводится родителям:
строка на вкладке «Расходы» раскрывается нажатием и показывает расшифровку
(что вошло в чек). Строка без комментария не раскрывается. Это лучший ответ на
вопрос «куда ушли деньги», чем категория, поэтому расшифровки стоит заполнять.
Комментарий к сбору (лист **«Сборы»**, колонка `Q`) на страницу не идёт: это
заметка для казначея.

Служебные пометки в комментариях («[?]», «уточнить», «уточняется», «TODO», «??»)
в журнале допустимы как временные, но на страницу попадать не должны — родитель
читает их как часть отчёта. `tools/verify.py` ищет их в собранной странице и
падает с указанием записи и поля.

Итоги для шапки берутся с листа **«Свод»** по подписи в колонке `B`
(«Поступило всего», «Остаток кассы», «Свободный остаток» и так далее), а не по
номеру строки: строки на листе сдвигаются при появлении новых итогов. Если
подпись переименовать, сборка остановится с явной ошибкой, а не подставит ноль.

## Как собрать страницу

Один раз — зависимости и код доступа:

```bash
python3 -m venv .venv
.venv/bin/pip install openpyxl cryptography
printf 'PASSWORD=код\n' > .env.local
```

Дальше вся сборка — один скрипт `tools/build.sh`:

```bash
./tools/build.sh                     # публичная версия на сегодня → index.html
./tools/build.sh 2026-08-17          # то же, но задним числом
./tools/build.sh 2026-08-17 --named  # именная версия → папка Свод на Диске
```

Скрипт печатает `report ok · N сборов · M детей` — числа стоит сверить с
журналом — и сразу прогоняет `tools/verify.py`. Если verify вернул не ноль,
скрипт падает: такой файл не публикуют. Именную версию verify не проверяет,
маскировки там нет по замыслу (см. «Именная версия для казначея»).

Единственный аргумент — дата отчёта, `ГГГГ-ММ-ДД`, по умолчанию сегодня. Из неё
выводятся и `AS_OF`, и `STAMP`, поэтому дата в заголовке и метка версии в подвале
разойтись не могут. Несуществующая дата (`2026-02-31`) отбивается до чтения журнала.

### Страницу надо пересобирать после каждой даты графика

Планка «надо к сроку» пересчитывается только в момент сборки: живая страница
сама себя не обновляет. Значит после каждой даты графика страницу надо пересобрать,
даже если новых платежей не было, — иначе родители видят вчерашнюю планку.

Замирают две разные вещи, и обе на дате сборки. `TODAY` внутри отчёта — константа
из `AS_OF`; от неё зависит всё, что страница считает сама: какой шаг графика
подсвечен, какие серые, «через N дн.» в календаре, рамка текущего месяца, окно
блока «Ближайший месяц». А сами суммы к сроку страница не считает вовсе — она
берёт их готовыми с листов журнала («Ждём к ближайшему сроку» на «Своде»,
«Долги_срок» по детям). Поэтому перед пересборкой журнал должен быть пересчитан:
формулы там опираются на `TODAY()`, и в файл попадает то значение, которое
сохранилось при последнем пересчёте.

По нынешнему графику ближайшие такие даты: **30.09**, **31.10**, **30.11**.
Актуальный список всегда виден на листе «График» и в шагах графика на самой
странице.

Код доступа в скрипте не записан: он читается из `.env.local` в корне
репозитория, строкой `PASSWORD=...`. Файл закрыт `.gitignore`. Если файла нет
или пароль пуст — сборка останавливается и говорит, что создать, а не собирает
страницу в открытом виде.

Почему скрипт, а не команда руками: правило в `.claude/settings.local.json`
записано один раз как `Bash(./tools/build.sh *)` и не зависит от даты. Раньше
там лежала команда с полным набором переменных, но без `AS_OF` и `STAMP` —
любая пересборка задним числом требовала подтверждения, а правило с зашитой
датой протухло бы на следующий день.

### Переменные окружения

`tools/build.sh` выставляет их сам. Таблица нужна, когда генератор запускают
напрямую — например при отладке.

| Переменная | Обязательна | Что делает |
|---|---|---|
| `SRC` | да | Путь к журналу `.xlsx` |
| `OUT` | да | Куда писать результат (для публикации — `index.html`) |
| `PASSWORD` | да | Код доступа. Данные шифруются AES-256-GCM, ключ через PBKDF2-SHA256 |
| `MASK` | да | `1` — публичная версия: имена вида «Артур Е.», фамилии не попадают в файл вообще |
| `AS_OF` | нет | Дата отчёта в формате `ГГГГ-ММ-ДД`. По умолчанию — сегодня |
| `STAMP` | нет | Метка версии в подвале. По умолчанию — текущие дата и время `ДД.ММ.ГГГГ ЧЧ:ММ` |
| `ALLOW_UNSAFE` | нет | `1` — снимает проверки `PASSWORD` и `MASK`. См. ниже, в норме не нужна |

### Предохранители

`PASSWORD` и `MASK` — не просто опции, а защита от публикации персональных
данных. Генератор проверяет их **до чтения журнала** и останавливает сборку:

- пустой `PASSWORD` → страница собралась бы в открытом виде, все цифры
  прочитал бы любой, кто открыл ссылку или скачал файл;
- `MASK` не равен `1` → в файл попали бы полные фамилии детей и казначея.

Проверку `tools/build.sh` запускает сам, но её можно прогнать и отдельно —
например над файлом, собранным раньше:

```bash
PASSWORD='код' .venv/bin/python tools/verify.py index.html
```

`tools/verify.py` расшифровывает payload собранной страницы и смотрит на то,
что реально лежит в файле, а не на то, что генератор напечатал в конце сборки:
число детей, сборов и расходов, итоги, сходится ли арифметика, замаскированы ли
имена детей и казначея, не осталось ли открытых данных payload и не уехали ли
на страницу служебные пометки. Выход `1` — хотя бы одна проверка упала, такой
файл не публикуют.

#### Именная версия для казначея

Ровно один сценарий, в котором `ALLOW_UNSAFE=1` законен: **именная
незашифрованная версия.** Аня работает со списком по фамилиям, код доступа ей
при этом не нужен. Собирается тем же скриптом:

```bash
./tools/build.sh 2026-08-17 --named
```

Файл пишется в `Свод/Отчёт_именной_2В.html` — **рядом с журналом на Google
Диске, не в репозиторий**. Пересобирать его стоит вместе с публичной версией:
именная от старой даты — это отчёт без последних трат и обязательств.

Что скрипт проверяет до сборки, чтобы фамилии не уехали в публикацию:

- каталог назначения лежит на Google Диске и **не** внутри рабочей копии
  (обе проверки — на случай, если `SRC` переопределили);
- `Отчёт_именной_2В.html` закрыт `.gitignore` — страховка на случай, если такой
  файл всё же окажется рядом и попадёт под `git add -A`.

Остальное на людях: файл не уходит на Pages и не пересылается в родительский чат.

Во всех остальных случаях `ALLOW_UNSAFE` не ставят: если сборка упала —
это сработавший предохранитель, а не помеха, и чинить надо `PASSWORD`/`MASK`.

### Код доступа

Данные шифруются AES-256-GCM, ключ выводится из кода через PBKDF2-SHA256,
**600 000 итераций**. Расшифровка идёт в браузере родителя, на сервер код не уходит.

Код **нечувствителен к регистру**, краевые пробелы срезаются: `Money2026`,
`money2026` и `MONEY2026` открывают отчёт одинаково. Это сделано ради телефона,
где включена автозаглавная буква и легко прилетает пробел из буфера.

Нормализация и число итераций продублированы в двух местах и обязаны совпадать:

- `norm_pass()` и `PBKDF2_ITERS` в `tools/build_report.py`;
- `decryptPayload()` на странице — итерации подставляются туда из `PBKDF2_ITERS`
  через `__ITERS__`, поэтому разойтись они не могут; нормализацию при правке
  нужно менять руками в обоих местах.

Если правило нормализации изменить, старые собранные страницы не откроются
прежним кодом — их нужно пересобрать.

Смена кода = пересборка страницы: код зашит в шифротекст, а не хранится рядом.
После пуша старый код перестаёт работать сразу, новый надо разослать родителям.

Сам код прописан в двух местах, и при смене правят оба:

1. заметка `Свод/_Доступ_к_сайту.md` на Google Диске — то, что читают люди;
2. `.env.local` в корне репозитория, строка `PASSWORD=...` — то, что читает
   `tools/build.sh`. Файл закрыт `.gitignore`.

Раньше код лежал ещё и в `.claude/settings.local.json`: команды сборки были
записаны там целиком, вместе с паролем, чтобы не разрешать запуск произвольного
python. Теперь разрешение выдано скрипту (`Bash(./tools/build.sh *)`), а пароль
из правил ушёл — менять его в двух местах вместо трёх и нечему разъезжаться.

### Дата отчёта

Задаётся первым аргументом скрипта в формате `ГГГГ-ММ-ДД`, по умолчанию —
сегодняшняя дата. Она идёт в заголовок страницы, в подвал и служит точкой
отсчёта для «через N дней» в календаре событий. Пересобрать отчёт задним числом:

```bash
./tools/build.sh 2026-09-01
```

Метка версии в подвале (`STAMP`) выводится из той же даты, отдельно её не
задают: иначе заголовок и подвал могли бы разъехаться.

### Доступ к Google Drive на macOS

Файлы в `~/Library/CloudStorage` защищены системой. Если сборка падает с
`PermissionError: Operation not permitted`, нужно выдать терминалу доступ:
Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску →
добавить приложение терминала и перезапустить его.

## Как обновить сайт

```bash
git add -A
git commit -m "отчёт на <дата>"
git push
```

Через минуту страница по ссылке обновится сама. Ссылка не меняется никогда.

## Смена учебного года

1. Скопировать текущий `index.html` в `archive/<год>.html`.
2. Поправить путь к журналу (`SRC`) в `tools/build.sh` и пересобрать.
3. Закоммитить и запушить. Ссылка в родительском чате остаётся прежней.

## Настройка Pages (один раз)

Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save.
